# BOSS 求职工作台 Web MVP

这是第一阶段的 Flutter Web 前端骨架，当前使用本地模拟职位数据演示完整的“筛选 → 结果 → 一键投递任务状态流”。

## 当前已实现

- Material 3 响应式工作台；
- BOSS 直聘职位筛选界面；
- 关键词、城市、薪资和高匹配筛选；
- 职位卡片、匹配度和职位详情弹窗；
- “开始筛选”加载状态；
- “一键投递”任务队列演示；
- 排队中、投递中、已投递状态变化；
- 桌面宽屏网格布局和窄屏列表布局。
- 苹果风格的浅色渐变背景、半透明毛玻璃面板和胶囊型按钮。
- 工作台、简历、投递记录、面试管理的前端导航骨架。
- 职位关键词动态添加（最多 5 个）。
- 全国省级行政区和地级城市选择入口，支持省份与城市二级筛选、多城市勾选和“不限地区”。
- 薪资最低值和最高值自定义输入，并提供 5-8K、10-12K 等快捷区间。
- “只看高匹配”和六大招聘平台默认灰色，点击后才高亮并参与筛选；再次点击可取消。
- 简历导入、自动识别中、识别完成、内容校对和保存结果的前端流程。
- 投递中心按平台、日期展示每日投递数量，并通过 REST 仓库读取后端统计。
- Flutter REST 客户端已覆盖平台账号、职位查询和批量投递任务接口。

## 启动方式

当前开发环境尚未安装 Flutter SDK。安装 Flutter 后，在项目根目录执行：

```bash
flutter pub get
flutter run -d chrome
```

也可以构建 Web 版本：

```bash
flutter build web
```

## 真实 BOSS 接入前必须完成

当前职位和投递流程是演示数据，不会访问真实平台，也不会发送真实简历。

真实接入需要新增后端授权适配器，并确认：

1. BOSS 直聘提供的正式职位/候选人接口范围；
2. OAuth 或其他授权方式；
3. 职位搜索、职位详情、投递和状态查询接口；
4. 简历文件传输和个人信息处理边界；
5. 平台允许的投递频率和用户确认机制。

建议真实接口只放在后端，不把平台密钥写入 Flutter Web。Flutter 只调用自己的业务 API。

## 本地后端联调

启动 Dart API 服务：

```powershell
.tools/flutter/bin/cache/dart-sdk/bin/dart.exe run server/main.dart
```

默认地址为 `http://127.0.0.1:8090`。Flutter REST 客户端可通过 `--dart-define=API_BASE_URL=...` 切换后端地址。

## 下一步代码拆分

当前为了便于快速预览，核心代码集中在 `lib/main.dart`。接入后端前建议拆分为：

```text
lib/
├── core/
├── models/
├── services/
├── features/workbench/
├── features/applications/
└── platform/boss/
```

其中 `platform/boss/` 只实现 BOSS 的授权适配器，工作台和投递状态机不直接依赖具体平台页面结构。简历模块的核心是“导入后自动识别和校对”，不再把 AI 改写作为主流程。

## 安全边界

- 不保存招聘平台密码；
- 不绕过验证码、短信验证或风控；
- 默认在最终投递前展示目标公司、职位、简历版本和发送内容；
- 简历文件和联系方式必须通过后端授权 API 访问；
- 所有真实投递任务都要有审计记录和可暂停能力。
## 平台账号与登录安全

工作台支持 BOSS 直聘、智联招聘、猎聘、前程无忧、鱼泡直聘和国聘的平台筛选。使用前可从左侧“平台账号”进入连接页面；未连接的平台在工作台点击时会引导到该平台官方登录页。

本项目不读取、不复制、不保存第三方 Cookie，也不通过 Cookie 冒充免密登录。生产环境应接入各平台正式开放平台提供的 OAuth、扫码授权或职位 API；如果平台没有授权接口，则只能由用户在官方页面完成操作。

详细方案见 [PLATFORM_ACCOUNTS.md](PLATFORM_ACCOUNTS.md)。
